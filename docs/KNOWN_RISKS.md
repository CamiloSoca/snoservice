# Riesgos abiertos antes del lanzamiento

**Estado: NO APTO PARA PRODUCCIÓN.** Estos puntos tienen impacto real; no se reemplazan con un build exitoso.

1. **Modelo contable incompleto.** Los snapshots de servicios, cobros manuales y cierres económicos funcionan en staging, pero no hay libro inmutable de comisiones efectivamente pagadas, retiros de propietarios, medios de pago, arqueo físico y ajustes compensatorios. `final_amount` en el cierre representa resultado económico, no efectivo contado ni saldo acumulado. No mostrar un saldo acumulado hasta que existan entradas/salidas trazables y conciliación. Hoy aún se permite borrar ciertos movimientos de una caja abierta; para una auditoría completa deben reemplazarse por ajustes compensatorios. No se añadieron saldos ficticios ni se recalcularon históricos.
2. **PIN heredados en claro.** Se eliminó su exposición por API y UI, pero la columna `barbers.pin` sigue conteniendo PIN legibles. Requiere migración de hash, rotación, prueba de login y eliminación controlada de valores en claro. Cambiar esos valores es irreversible en staging y requiere aprobación específica; no se hizo. El secreto administrativo está en variables del servidor, sin hash ni rate limiting distribuido demostrado.
3. **Producción tiene otro esquema y datos.** Hay 3 reservas canceladas y 2 barberos; faltan 12 columnas, 5 restricciones y funciones financieras. No se confirmó quién es propietario; una comisión de 100% no prueba titularidad. Las migraciones preparadas no se ejecutaron ni ensayaron sobre un clon de producción. No existe una rama Supabase del proyecto y no se verificó un backup restaurable. Publicar código nuevo ahora rompería rutas.
4. **Concurrencia y extremo a extremo.** La exclusión GiST protege transaccionalmente los solapamientos en staging, pero falta la prueba automática con dos conexiones simultáneas y un flujo HTTP completo con fixtures aislados. El cierre doble fue probado con transacción, no con dos clientes HTTP concurrentes.
5. **Calidad y rendimiento.** ESLint sigue fallando en código propio (61 errores, 22 advertencias); hay `any` y reglas de hooks por resolver. Next advierte que `middleware.ts` está obsoleto. Las medidas p50/p95 tienen sólo siete muestras calientes por ruta; falta instrumentación de navegador y volumen representativo. La disponibilidad pública todavía ronda 239/336 ms en ese ensayo.
6. **Seguridad residual.** No se demostró rate limiting distribuido del login admin ni revisión de dependencias con una fuente de vulnerabilidades actualizada. `security/booking-flexible-production-apply.sql` contradice la prohibición de solapamientos y jamás debe ejecutarse. La reserva antigua almacena fecha sin año; el guard resuelve desde `created_at` y rechaza datos históricos ambiguos, que exigirán tratamiento manual.

No se han cambiado datos de producción, `main`, GitHub remoto, Vercel ni Netlify.
